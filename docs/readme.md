# File Rules

- `main.cpp` only starts the application.
- One class = one `.hpp` + one `.cpp`.
- One file = one responsibility.
- One folder = one feature.
- Avoid files named `Utils`, `Helpers`, `Common`, etc.

## Create a new file when...

- A class has a single clear purpose.
- Code could be reused elsewhere.
- A file starts handling multiple responsibilities.
- A file becomes difficult to navigate.

---

# Folder Responsibilities

| Folder | Purpose |
|---------|---------|
| `blocker/` | Block apps & websites |
| `config/` | Load/save configuration |
| `monitor/` | Detect coding activity, running processes |
| `session/` | Goals, timers, streaks |
| `storage/` | Files, databases, serialization |
| `assets/` | Icons, templates, static resources |

---

# Configuration

## TOML → Data

Use for things users configure.

Examples:

- Settings
- Theme
- Timers
- Lists
- Blocked apps
- Blocked websites
- File paths

Never put logic here.

---

## Lua → Behavior

Use for things users can customize.

Examples:

- Achievements
- Rewards
- Startup scripts
- Event hooks
- User plugins
- Custom automation

Never use Lua for core application logic.

---

## C++ → Core Application

Use C++ for everything that makes DevQuest work.

Examples:

- Process detection
- Reading `/proc`
- Website blocking
- File system
- Networking
- Parsing config
- Terminal UI
- Business logic

---

# Modern C++

Prefer:

- `std::string`
- `std::vector`
- `std::optional`
- `std::filesystem`
- `std::chrono`
- `std::unique_ptr`

Avoid:

- Raw `new` / `delete`
- Global variables
- Giant source files
- God classes

---

# General Principles

- Keep functions short.
- Keep classes focused.
- Prefer composition over inheritance.
- Write code that is easy to delete or replace.
- If something feels "temporary", leave a TODO.
- Every commit should compile.

---

# Decision Guide

Need to store values?
→ **TOML**

Need user-defined behavior?
→ **Lua**

Need OS access, performance, or application logic?
→ **C++**

Data describes.
Lua customizes.
C++ decides.
